# ExecPlan：识别拷贝漫画「空目录」软封锁

## 摘要

连续解析两本拷贝漫画后，第二本报「镜像均仅识别到 1 话」，第一本被误判为单话作品。实测站点限流时章节接口仍返回 HTTP 200「请求成功」，但加密内容解出来是 `count: 0`、`chapters: []` 的空目录。app 把它当作「没拿到数据」，继续网页渲染兜底并轮换 3 个镜像，一次解析发出 12–15 个请求，进一步加重限流。只改拷贝漫画解析与请求标识，不动下载逻辑。

## 用户价值

- 被限流时立即停下，提示「约 N 分钟后再试」，不再误报「仅 1 话」，也不再把多话作品当单话加载。
- 限流期间再次解析直接本地拒绝，不再发请求。
- 一次正常解析请求更少。

## 改动

| 项 | 做法 |
|---|---|
| 识别空目录 | `comicdetail` 返回能解密、结构完整但章节总数为 0 → 抛 `parseBlocked`，不再走渲染 DOM 与镜像轮换（已有逻辑：`parseBlocked` 是阻断错误） |
| 冷却范围 | 封的是 IP，冷却按「拷贝漫画家族」整体生效，而不是单个域名；时长 20 分钟 |
| 请求标识 | 统一为完整的 Safari User-Agent（接口、渲染 WebView、图片下载） |
| 日志 | `comicdetail` 探测中被吞掉的错误写入日志 |

## 决策记录

- 判定条件：能解析出分组、且每个分组 `chapters` 为空、`count` 为 0。解不开或结构不认识时不判定为限流，继续走原解析流程，避免误报。
- 判定后抛 `parseBlocked`：镜像循环里它本来就是阻断错误，会直接停止，不再渲染 DOM、不再换镜像。
- `AntiBanGuard` 对拷贝漫画所有镜像共用一个冷却键 `copy-family`；冷却内再次解析直接本地报「限流冷却中，请约 N 分钟后再试」，不发请求。
- 冷却提示 ≥2 分钟时按分钟显示。
- 实测依据：同一接口，第一次返回约 9 KB（解密 43 话），随后各种请求头组合都只返回 610 字节（解密为 `count: 0`）。说明是按频率/IP 的软封锁，与请求头无关；换完整 User-Agent 是为了降低被单独识别的概率，不是这次的直接原因。
