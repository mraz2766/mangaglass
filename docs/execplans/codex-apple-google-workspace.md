# ExecPlan：MangaGlass Codex 式 macOS 工作区重构

## 摘要

将 MangaGlass 从单页卡片界面重构为完整的桌面工作区。视觉以 Codex 式高密度、安静的信息布局为主，使用原生 macOS 材质与单一品牌蓝强调交互状态；Google 风格的清晰层级和语义状态色用于增强可扫读性。

本次为大幅 UI 改版，版本从 `1.2.17` 升至 `1.3.0`。解析、下载、风控和持久化协议不变。

## 用户价值

- 链接解析、章节选择与加入队列仍是一条连续流程，但每一步的当前状态和下一步操作更明确。
- 队列、历史和设置不再藏在菜单或弹窗中，可随时从侧栏进入。
- 章节很多时可以搜索，并保证批量选择只影响当前可见结果。
- 浅色、深色和跟随系统保留；应用不再因多套皮肤产生不一致的颜色和组件行为。

## 范围

范围内：

- 将 `ContentView` 拆分为侧栏应用壳层、下载工作台、队列、历史、设置和共享 UI 组件。
- 重新建立语义化设计系统，移除多皮肤分支。
- 将下载管理器改为应用内页面，保留所有队列控制、失败详情、风控和确认操作。
- 为章节增加不持久化的搜索状态，搜索结果驱动现有的“可见章节”批量操作。
- 更新版本、截图和应用构建产物。

范围外：

- 不新增漫画库、收藏、阅读器、代理设置或第三方依赖。
- 不修改下载、解析、网络、风控和持久化数据格式。

## 约束

- 使用 macOS 13 与 Swift 6.2 可用的 SwiftUI API。
- 主色为 `#0A5BD8`；成功、警告、失败只能使用语义状态色。
- 使用系统字体（SF Pro）和等宽系统字体（SF Mono）；使用 4pt 间距栅格、8/12pt 圆角、细分割线与有限材质。
- 动效使用 180ms 的页面过渡、选章操作栏出现和任务详情展开，并在减少动态效果时禁用非必要动效。
- 每次可见 UI 修改后都构建应用并替换 `/Applications/MangaGlass.app`；完成时更新本计划的进度、决策、意外发现和结果。

## 已确认事实

- 应用目前是 `ContentView` 单页布局，下载管理器使用独立 `DownloadManagerView` sheet。
- `MainViewModel` 已有解析、章节选择、队列、历史、Cookie、目录、日志、外观模式和持久化状态。
- `RecentComicRecord` 已保存最近访问时间，最多保存八项。
- 当前四套 `AppColorTheme` 会驱动 `DesignSystem` 的颜色与圆角分支。
- 项目当前没有测试 target；构建与端到端人工验收是当前可用的验证基础。

## 视觉与交互设计

- 视觉主张：深浅自适应的中性工作台，主工作区最突出，封面和状态仅提供必要上下文。
- 内容结构：侧栏负责导航和队列概览；下载页负责链接、解析和选章；队列页负责执行和异常处理；历史与设置各自承担单一管理任务。
- 动效：页面切换淡入与轻位移、选中章节操作栏从底部出现、失败详情按行展开。

## 实施计划

### 里程碑 1：建立统一应用框架与设计系统

- 创建 `WorkspaceDestination` 路由和固定侧栏，包含下载、队列、历史、设置及实时队列摘要。
- 将 `ContentView` 降为应用壳层；将具体工作页面拆分到 `UI/Workspace/`。
- 重写共享颜色、字体、间距、按钮、列表行、分段控件、状态标签、空状态和确认层样式。
- 删除 `AppColorTheme` 与 `colorTheme` 的 UI 状态和样式分支，保留 `AppThemeMode`。

### 里程碑 2：下载工作台与章节搜索

- 重建链接输入、站点入口、下载目录、解析状态、漫画 Inspector、卷过滤和章节选择页面。
- 新增 `chapterSearchQuery`，让可见章节、全选、清空与加入队列遵守当前搜索结果。
- 保留原有单选、Command 多选、框选、排序、按卷批量选择、错误重试、日志和恢复队列提示。

### 里程碑 3：队列、历史和设置页面

- 将下载管理器内容迁移为队列页面，保留筛选、控制、失败原因、风控操作、进度和确认对话框。
- 以紧凑行列表呈现最近历史，支持重新加载、删除和清空。
- 集中外观模式、下载目录、Cookie、站点入口和清缓存设置；Cookie 默认隐藏。

### 里程碑 4：版本、视觉验证和交付

- 更新构建脚本版本为 `1.3.0`，构建并安装 `/Applications/MangaGlass.app`。
- 在浅色/深色及 `1080×760`、`720×540` 窗口检查布局、焦点和文本截断。
- 验证解析、搜索、选择、队列、恢复、失败、历史、日志、Cookie、目录与缓存操作。
- 使用真实应用截图更新 `assets/home.png`，完成本计划的结果回顾。

## 验证方式

- `swift build` 必须通过。
- `./scripts/build_app.sh --install` 必须生成并安装 `1.3.0` 的应用。
- `./scripts/build_dmg.sh` 必须通过，以验证两个构建脚本版本一致。
- 人工端到端验证：输入链接、解析、卷筛选、搜索、单选/Command 多选/框选、加入队列、暂停、继续、重试、取消、历史重载、清缓存和重启恢复。

## 风险

- SwiftUI 视图拆分可能导致环境对象、确认状态或手势坐标空间断裂。
- 使用查询过滤后，选择计数和“全选可见”语义必须与现有下载行为一致。
- 大型视觉改版必须保留漫画柜风控、恢复队列和失败详情等低频但关键路径。

## 决策记录

- 决策：采用 Codex 主导的完整工作区，而不是保留单页卡片布局。
  原因：用户已确认需要完整侧栏架构与统一视觉语言。

- 决策：统一为一套品牌系统，仅保留浅色、深色和跟随系统。
  原因：现有四套皮肤会增加样式分支，无法形成一致的应用体验。

- 决策：功能只重组和强化现有能力，不增加本地漫画库或阅读器。
  原因：用户已明确选择此边界，服务和数据模型保持低风险。

- 决策：用自定义 `MGEmptyState` 代替系统 `ContentUnavailableView`。
  原因：项目最低支持 macOS 13，而系统组件仅从 macOS 14 起可用；自定义组件保持了相同的空状态信息层级和兼容性。

- 决策：搜索结果之外的章节选择保持不变，但“清空”和“加入队列”仅作用于当前可见章节。
  原因：搜索不应破坏用户已有选择，同时批量下载必须严格遵守当前筛选范围。

## 意外发现

- macOS 13 不支持 `ContentUnavailableView`，已替换为项目内的 `MGEmptyState`。
- 默认 `1080×760` 窗口扣除侧栏和边距后内容区接近窄布局断点；已将工作台纵向布局断点收紧到 760pt，使默认窗口保持 Inspector 与章节区并列。
- `swift build` 会修改项目中已跟踪的 `.build/` 产物；这些构建输出保留为构建过程的自然结果，未尝试覆盖或清理。
