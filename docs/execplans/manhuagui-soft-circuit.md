# ExecPlan：漫画柜温和提效与软熔断

## 摘要

本次按用户指定参数调整漫画柜下载：章节并发改为 4，单章节图片并发保持 2，图片请求间隔改为 280-520ms。同时新增漫画柜软熔断：遇到 403/429/503 时停止当前漫画柜批次、保留队列，并由用户自行打开网页判断是否继续。

不做强制冷却期，不禁止用户重新下载，不实现代理、绕封禁或伪装访问。用户明确表示不需要执行 Test Plan，因此本次只做代码修改与必要的静态检查，不运行构建验证。

## 用户价值

- 漫画柜下载在现有可慢速下载的基础上略微提效。
- 疑似风控时应用不继续扩大请求，而是停下来让用户判断。
- 用户可以自行打开漫画柜网页确认是否被封，并手动继续队列。
- Copy 漫画下载不受漫画柜软熔断影响。

## 范围

范围内：

- 调整漫画柜章节并发与图片请求间隔。
- 为漫画柜 403/429/503 增加软熔断状态、日志与 UI 操作入口。
- 修正失败重试路径使用站点感知并发。

范围外：

- 不运行完整 Test Plan。
- 不做强制冷却期。
- 不修改漫画柜解析逻辑。
- 不实现规避风控能力。

## 约束

- 用户指定漫画柜章节并发为 4。
- 用户指定单章节图片并发保持 2。
- 用户指定漫画柜图片请求间隔为 280-520ms。
- 软熔断不能禁止用户手动继续下载。

## 实施计划

### 里程碑 1：参数调整

- 将漫画柜章节并发改为 4。
- 将漫画柜图片请求间隔改为 280-520ms。
- 保持单章节图片并发 2。

### 里程碑 2：软熔断状态

- 新增漫画柜软熔断状态，记录状态码、host、章节、提示文案。
- 403/429/503 触发软熔断后停止当前漫画柜批次，并把 running 漫画柜任务放回 queued。
- 软熔断期间调度器跳过漫画柜 queued 任务，但不影响 Copy 任务。

### 里程碑 3：用户操作入口

- 主界面和下载管理器展示软熔断提示。
- 提供“打开网页检查”和“我已确认，继续下载”。
- 用户继续时清除软熔断并按站点感知并发继续。

## 决策记录

- 决策：软熔断只阻止漫画柜任务继续调度，不阻止 Copy 漫画任务。
  原因：漫画柜风控不应影响其他站点下载。
- 决策：触发软熔断时将 running 漫画柜任务放回 queued。
  原因：用户确认后可以继续原队列，而不是手动重建任务。
- 决策：不运行 `./scripts/build_app.sh`。
  原因：用户明确表示不需要 Test Plan。
