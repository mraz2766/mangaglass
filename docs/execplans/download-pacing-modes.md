# ExecPlan：下载节奏（智能 / 偏效率 / 偏稳妥）

## 摘要

用户实测确认《七大罪》剩余几话的 TLS 错误来自站点限流。本次分析触发原因，重做所有站点的下载频控，并在设置中新增「下载节奏」，默认「智能」，可切换「偏效率」「偏稳妥」。

## 触发原因（代码 + 队列时间戳）

1. **持续高量、没有休息**：漫画柜所有图片共用一个 240–460ms 的节拍器，约 2.9 张/秒；63 话约 2500 张图连续拉取，中间没有任何停顿，远超真人阅读（约 5–10 秒一页）。
2. **批次起步并发突刺**：漫画柜章节并发 4，开始/继续时 3–4 话在同一秒同时请求章节页（队列记录：02:02:57 同时开始 3 话）。
3. **限流信号没被识别**：站点用断开 TLS 连接限流，但应用把它转换成「页面解析失败」文本，不算限流，也不降速；第一话失败后仍每约 5 秒开始一话，30 秒内连续撞墙 6 次，延长了封禁。
4. **只有 HTTP 403/429/503 才会暂停**，且漫画柜暂停后必须手动继续，没有自动冷却恢复。

拷贝漫画、包子漫画存在同类结构问题（固定并发、无章节间隔、无长时间休息）。

## 设计

`DownloadPacingMode`：`smart`（默认）/ `efficient` / `safe`。每个站点族（拷贝、漫画柜、其他）一组参数：

| 参数 | 含义 |
|---|---|
| 章节并发（范围） | 同时下载的话数；智能模式在范围内自适应 |
| 每话图片并发 | 单话内并行图片数 |
| 图片间隔 | 站点共享节拍器的随机间隔（毫秒） |
| 章节间隔 | 相邻两话开始请求章节页的最小间隔 |
| 休息 | 每连续 N 话休息一段时间 |
| 冷却 | 识别到限流后整站暂停时长，到点自动继续 |

智能模式自适应（AIMD）：连续成功一定张数后升一档（并发 +1 / 间隔缩短），任何限流信号立即降到下限并加大间隔。

限流信号：HTTP 403/429/503、TLS/连接被重置、超时、返回非图片页面。漫画柜章节页连续 2 次连接被重置 → 整站进入冷却，失败的话回到排队，冷却结束自动继续。

## 范围

- 新增 `Services/DownloadPacing.swift`（模式、站点族、参数表、自适应状态）。
- `DownloadCoordinator`：章节并发、章节间隔与休息、图片间隔/并发、限流信号、漫画柜连接限流自动冷却。
- `CopyMangaAPI`：连接被重置类错误保留为可识别类型。
- `DownloadIntegrity.HostRequestBudget`：间隔由参数决定。
- `MainViewModel`：`downloadPacingMode` 持久化；移除按站点硬编码的并发；「Copy 图片并发」由节奏模式取代。
- 设置页：「下载节奏」；下载页风控提示显示自动继续倒计时。
- 测试。

## 约束

- 大幅调整下载/并发策略：`1.13.1` → `1.14.0`。
- 「智能」默认比旧版更克制（漫画柜旧版即约等于本次的「偏效率」）。

## 决策记录

- 「Copy 图片并发 4–8」选择器移除，由节奏模式决定（安全 3、智能 4–6 自适应、效率 6–8）；旧存储值不再读取。
- 混合站点队列的章节并发取各站点当前值的最小值，偏保守。
- 漫画柜 HTTP 403 仍需用户到网页确认（可能是验证码）；连接被断开类限流改为自动冷却并自动继续，期间失败的章节回到队列。
- 拷贝漫画软熔断也改为冷却到点自动继续（之前需手动点击）。
- 冷却倒计时通知用每秒刷新的 TimelineView，暂停期间也能实时显示。

## 结果

- 版本 `1.14.0`；`swift test` 68 项通过（3 项按设计跳过），新增 9 项（模式单调性、智能模式比旧漫画柜节奏更克制、AIMD 升降档、拷贝图片并发自适应、章节间隔与休息排程、冷却推迟、限流信号识别、站点归类、设置传递）。
- 设置页快照核对「下载节奏」区块与各站点参数说明。
- 未实测：真实站点在三种模式下的长时间运行表现。
