# ExecPlan：修复漫画柜图片地址重复编码，并排查各站点下载逻辑

## 摘要

七大罪有 4 话（番外篇等）始终下载失败，重试会引发一串注定失败的请求并触发限流冷却。实测根因：漫画柜返回的图片文件名已是百分号编码（如 `IMG_5052%E5%89%AF%E6%9C%AC`），而目录名是原始中文（`番外篇13`）；`URL(string:)` 遇到中文会把整串再编码一遍，`%` 变成 `%25`，地址 404。用户要求同时检查其他站点的下载逻辑。

## 排查结论

| 站点 | 问题 | 实测 |
|---|---|---|
| 漫画柜 | 文件名重复编码 → 404，且 6 个图片域名各试一次、每次计入「404 失败」 | 同一张图：重复编码 404，单次编码 200（129 KB） |
| 漫画柜 | 默认图片域名 `cf.hamreus.com` 当前对所有图片 404；`i/us/eu` 正常 | 首次必白跑一次 `cf` 并计一次 404 |
| 包子漫画 | `www.baozimh.com` 现在对非浏览器返回 JS 验证页（403「正在验证浏览器」），解析和取图都会失败 | `www.twmanga.com` 目录页与章节跳转正常；图片 `bzcdn.net` 正常；章节无分页 |
| 拷贝漫画 | 图片地址同样经过 `normalizedURL`，存在同类隐患（目前未见实例） | 高清替换基于已编码地址，无问题 |
| 通用 | 章节/漫画名清洗后可能以 `.` 开头（变隐藏文件夹）、为空、或超长 | 代码审查 |

## 改动

1. 新增宽松地址构造 `MGURL.lenient`：只编码真正非法的字符（中文、空格等），保留已有的 `%XX`，杜绝重复编码。漫画柜拼图、`normalizedURL`、包子章节链接、分享入口链接统一改用它。
2. 漫画柜图片 404 时，若还有备用域名，不计入章节「404 失败」，只有所有域名都 404 才计数；成功的域名照旧在本次运行中优先。
3. 包子漫画：页面请求先走 `www.twmanga.com`，失败或遇到验证页再回退 `www.baozimh.com`；遇到验证页不触发站点冷却。站点配置（显示名、已保存的队列）不变。
4. 文件名清洗：去掉开头的 `.`、空名回退为「未命名」、按 UTF-8 截到 200 字节。

## 决策记录

- `MGURL.lenient` 只编码「非 URL 合法字符」并保留 `%`：已编码的部分原样保留，原始中文/空格编码一次；纯 ASCII 地址（含 `%2F`、`+` 等签名参数）不变。替换了漫画柜拼图、`normalizedURL`（三站图片地址都经过它）、分享入口、单话直链、包子章节链接。
- 漫画柜 404：只有最后一个候选域名也 404 才计入章节「404 失败」；中间域名 404 只切换备用域名。成功域名在本次运行优先（原有逻辑）。默认域名 `cf.hamreus.com` 保留：它在部分网络下是唯一可用的，404 现在只多一次请求、不再累计失败。
- 包子漫画：`CopyMangaAPI.baoziMirrors = [twmanga, baozimh]`；每个域名用独立的站点配置请求，所以 baozimh 的 403 只冷却它自己，不影响 twmanga。站点配置 `.baoziManga`（显示名、已保存队列、`site == .baoziManga` 判断）不变。取消请求直接抛出，不当作「换下一个域名」。
- 文件名：下载器的 `sanitize` 改为调用 `DownloadOutputLayout.sanitize`，两处规则统一，「已下载」检测与实际写入保持一致。
- 包子章节分页：实测两部漫画的章节页都是单页（「點選進入下一話」指向下一话），不是缺陷，未改。
