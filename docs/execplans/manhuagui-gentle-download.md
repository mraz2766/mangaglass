# ExecPlan：漫画柜下载改为「像人在看」的节奏，连接失败立即停

## 摘要

用户反馈：一用 app 下载漫画柜，网站（含浏览器）就打不开。日志（09:28–09:31）显示：章节页正常 → 每张图先打 `cf.hamreus.com` 得 404 → 约 20 秒内 `i.hamreus.com` 首次连接即 TLS 失败 → 随后轮换 eu/us/us2/eu2，每个卡约 10 秒并重试 2–3 次，2 话 × 每话 2 图并行，两分钟内几十次连接。之后 www 与图片域名在隧道与系统代理两条路径上都不可达：当前节点 IP 被封。

## 根因

1. 节奏过快：「智能」允许 1–3 话并发、每话 2 图并发；`manhuaGuiPacer` 只错开请求**开始**（0.3–0.6 秒），请求卡住时后续仍不断发起。
2. 每张图先打 `cf.hamreus.com`（当前对所有图片 404），一批 404 像扫站。
3. 连接失败（TLS/超时/断开）时轮换全部图片域名并重试；这些域名同属一站、封的是 IP，换域名只会放大请求数，延长封禁。
4. 连续 2 话失败才冷却，冷却结束直接按原并发恢复。

## 改动

| # | 项 | 做法 |
|---|---|---|
| 1 | 节奏 | 漫画柜三档都改为：每话图片 1 张接 1 张；稳妥/智能一次 1 话，偏效率最多 2 话；图片间隔 稳妥 1.0–1.8 秒、智能 0.8–1.5 秒、偏效率 0.6–1.1 秒；章节间隔相应加大 |
| 2 | 图片域名 | 默认与候选顺序改为 `i → us → eu → us2 → eu2 → cf`；404 仍切换备用域名 |
| 3 | 连接失败 | 漫画柜图片遇到 TLS 失败 / 超时 / 连接断开 / 无法连接：不重试、不换域名，本话失败并立即进入冷却（原为连续 2 话） |
| 4 | 冷却与试探 | 冷却按次数递增：8 → 16 → 32 分钟（上限 60，按节奏档位基数）；有一话成功后归零。恢复时因为图片串行，第一个请求就是试探，失败立刻再冷却 |

## 约束

- 普通修改（下载策略修正）：`1.18.1` → `1.18.2`。
- 只改漫画柜；拷贝漫画、包子不变。
- 测试离线：节奏表、域名顺序、连接失败分类、冷却递增。

## 决策记录

- 节奏：漫画柜三档每话图片并发都为 1；稳妥/智能章节并发固定 1（不再自动提速），偏效率 1–2（连续 60 次成功才升到 2）。图片间隔 稳妥 1.0–1.8s、智能 0.8–1.5s、偏效率 0.6–1.1s；章节间隔 8–12s / 5–8s / 3–5s；休息 每 8 / 12 / 20 话。
- 域名：`manhuaGuiImageHosts` 改为 i → us → eu → us2 → eu2 → cf；拼图默认域名同步改为 i（两处保持一致）。
- 连接失败：漫画柜图片请求遇到 TLS 失败 / 超时 / 连接断开 / 无法连接时，`retrying` 立即抛出（不重试），候选循环也不换域名（`isManhuaGuiHost` 排除）；本话失败后 `handleConnectionThrottle` 对漫画柜第 1 次就进入冷却（原来连续 2 次）。404 仍按原逻辑换备用域名。包子漫画的连接失败换域名逻辑不变。
- 冷却递增：`escalatedCooldown(base:strikes:)` = 基数 × 2^次数，上限 60 分钟；任何一话漫画柜下载成功后清零。图片串行后，恢复时的第一个请求本身就是试探，失败只多一次请求就再次冷却。
- 章节页请求本来就是单次尝试（`retryTimes: 1`），未改。
- 未做行为级（桩网络）测试：需要伪造漫画柜加密章节页或磁盘清单，成本高；以单元测试 + 代码路径审查覆盖。

## 结果

- 版本 `1.18.2`；`swift test` 99 项通过（4 项按设计跳过）；更新 2 个旧断言（原智能档可升到 3 话、cf 为首个备用），新增节奏、冷却递增、连接失败分类测试。
- 未联网实测：当前节点被封，需用户换节点、浏览器确认能打开后再下载验证。
