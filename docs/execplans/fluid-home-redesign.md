# ExecPlan：大封面首页与流畅组件改版

## 摘要与用户价值

首页采用 64 pt 导航、常驻大封面和通高章节网格，让封面与大量章节同时可见。保留颜色体系，使用 SwiftUI 原生实现 Fluid Functionalism 的明确悬停和统一状态过渡。

## 范围与约束

- 首页、共享组件、队列工具栏、设置对齐和选择行为；不改变网络与持久化格式。
- 显著改版，版本 1.4.2 → 1.5.0。构建安装至 `/Applications/MangaGlass.app` 后中文提交。
- 默认 1200×800，最小内容 720×540。封面栏按窗口宽度为 280/240/180 pt；章节 38 pt 高、160 pt 最小宽。

## 已确认事实

- 当前小窗口把封面改为摘要；分类区域额外占高。
- 隐藏分类会丢选择，队列开始复用首页加入逻辑。

## 实施计划

1. 重排首页和导航，分类改弹出面板、分组支持吸顶与折叠、封面支持预览。
2. 统一共享动效、按钮、搜索及选择组件，调整队列和设置。
3. 筛选保留选择，首页按全部选择入队，队列开始独立。
4. 逻辑测试、构建与实机验收，记录可验证结果和限制。

## 修改文件

- `Sources/MangaGlass/UI` 下页面与共享组件。
- `Sources/MangaGlass/App` 下窗口与选择状态。
- `Package.swift`、测试、构建脚本及本计划。

## 验证方式

- 独立 scratch path 的 Swift 测试和 Release 构建。
- 验证跨分类选择、全部入队与独立启动队列。
- 实机观察大封面、网格、焦点及多尺寸布局；构建安装并核对 1.5.0。

## 决策与风险

- 不引入 React 依赖，借鉴已有参考项目的交互原则。
- 选择集合不随显示过滤改变；折叠状态仅会话保留。
- 不为验收启动真实下载，使用测试验证入队边界。
- 用户追加要求：所有应用内 Logo 统一通过 `BrandMarkView` 裁切连续圆角，半径为边长的 22%。
- 删除未使用的 `WindowAccessor`，最小内容尺寸只由 `ContentView` 的 720×540 与 SwiftUI 窗口策略管理。
- 分组全部折叠时继续显示分组标题，避免无法重新展开；折叠后的选择计入隐藏数量。
