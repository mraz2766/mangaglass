# ExecPlan：减少解析请求、目录缓存落盘、解析与下载共用限流状态

## 摘要

拷贝漫画按 IP 统计请求频率，超限后返回「成功但 0 话」的空目录（1.16.1 已能识别）。根因是请求太多太密：一次解析最多约 15 个请求（章节接口 3 次、渲染整页、逐话「下一话」爬取、3 个镜像重来），且重启、从书架打开都会重新解析。本次从源头减少请求，并让解析和下载看到同一份限流状态。不改下载节奏档位、图片下载与校验逻辑。

## 用户价值

- 打开解析过的漫画（12 小时内）直接显示，不再联网；需要最新目录时手动刷新。
- 正常解析一次约 2 个请求，限流概率明显下降。
- 连续解析多本时自动间隔，界面显示倒计时，不会再一口气打满。
- 下载触发冷却时，解析也一起等待；反之亦然。

## 决策记录

- 缓存检查放在 `MainViewModel.loadComic`：命中缓存直接显示并记日志，不进入解析间隔等待；「刷新」走 `forceRefresh` 绕过缓存。`MainViewModel(persistsState: false)` 只用内存缓存，测试不碰真实文件。
- 恢复上次会话时，从缓存补上「目录更新于」时间；缓存里没有就显示「目录已就绪」。
- 解析间隔从上一次拷贝漫画联网解析**结束**算起（更保守），等待时显示倒计时，可被新的解析请求取消。
- 「目录不完整 / 空目录」不再换镜像，直接停止；只有域名解析失败、连接失败、超时、证书错误、网关类 5xx 才换。TLS 握手失败和连接中断不算（站点常用来限流）。
- 渲染整页和逐话「下一话」爬取只在章节接口完全拿不到可用结果时兜底。
- 下载侧：可疑失败的连续阈值统一从 3 降到 2（也作用于损坏页面等其他可疑失败，更保守）；「未解析到图片」冷却 5 → 20 分钟。下载进入拷贝漫画冷却时同步阻断解析，用户提前继续时一并解除。
- 用桩站点（`URLProtocol`）固定请求数：正常解析 = 2 个请求；空目录 = 2 个请求且只访问一个域名。
