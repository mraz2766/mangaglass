# ExecPlan：下载完整性、统一限速与交互性能

## 摘要

在保留现有站点、目录结构和用户操作方式的前提下，补齐下载内容校验、章节完整性记录、统一 host 请求预算、冷却后渐进恢复及缺失页重试。同步回归并强化加入队列后清除选择、成功动效以及首页和队列的大数据量交互性能。

本次不照搬 `manga-downloader` 的高并发默认值，只借鉴章节／页面分层、逐页重试和内容格式识别思路，继续采用适合拷贝漫画风控环境的保守策略。

## 用户价值

- “已完成”代表所有页面都是真实可识别的图片，不会把 HTML 风控页或损坏文件当成漫画。
- 异常退出、部分失败或再次重试时，只请求缺失或损坏页面，减少流量和触发风控的概率。
- 冷却后先单线程试探，确认恢复后再回到正常并发。
- 大量卷／话和长队列下，选择、折叠、筛选与进度刷新保持流畅。

## 范围

范围内：

- 校验响应 MIME、图片文件头和最小有效长度；拒绝 HTML、JSON、验证码和损坏载荷。
- 校验已有文件，合法页面直接复用，损坏页面移除后重下。
- 每章维护原子写入的隐藏完整性清单，记录预期页数、已验证页码、格式、大小和完成状态。
- Copy 章节解析、镜像请求和图片下载共享按 host 的请求预算；限制活跃请求并保留不同请求类型的间隔。
- 风控冷却结束后以章节并发 1 试探，连续成功后恢复并发 2。
- 重试时优先使用已有章节图链，只下载清单中缺失或损坏页面；图链不可用时再重新解析章节。
- 缓存章节筛选、分组计数和队列摘要，减少 SwiftUI `body` 中重复全量扫描。
- 回归加入队列后清除选择和成功反馈动效。

范围外：

- 不新增 CBZ、图片转码、文件名模板或用户可调任意并发数字。
- 不改历史记录格式，不删除用户已验证有效的下载文件。
- 不绕过验证码或站点访问控制。

## 约束

- 本次涉及网络并发、持久化和状态流重构，属于大幅修改，版本 `1.6.1` → `1.7.0`。
- SwiftUI，兼容 macOS 13，不引入第三方框架。
- 图片和清单读写不得阻塞主线程；所有落盘使用临时文件或原子替换。
- 队列快照向后兼容 1.6.x；旧任务缺少新字段时按安全默认值恢复。
- 完成后构建并安装 `/Applications/MangaGlass.app`，核对两个 Bundle 版本并以中文 `feat:` 提交。

## 已确认事实

- 1.6.1 已在成功入队后清除选择，并显示“已加入 N 话”及轻量扩散动效。
- 首页章节坐标缓存、重复拖拽状态去重、下载进度与整页刷新隔离已经实现，但分组统计和多个派生数组仍会在 SwiftUI 渲染期间重复遍历。
- 当前 Copy 同时下载 2 章，每章最多 3 个图片任务；章节解析和图片分别使用不同节拍器，同一 host 的总活跃请求没有统一上限。
- 当前 HTTP 2xx 数据未经 MIME 或魔数验证便以 `.jpg` 写入；已存在文件仅按路径判断，零字节、HTML 或损坏文件也会被跳过。
- 图片请求最多执行 3 次，支持指数退避、随机抖动和 `Retry-After`；队列恢复可复用落盘文件，但没有章节级完整性清单。

## 实施计划

### 里程碑 1：内容校验与完整性清单

- 实现图片格式嗅探、响应校验、已有文件校验和原子章节清单。
- 章节只有在预期页数全部验证通过后才标记完成。

### 里程碑 2：缺失页恢复与统一 host 预算

- 让每页任务返回可持久的校验结果，失败时保存不完整清单。
- 将 Copy 章节和图片请求接入同一 host 调度器，统一限制并发、节拍和惩罚。
- 冷却结束后进入探测模式，连续成功达到阈值后恢复正常并发。

### 里程碑 3：交互性能与反馈回归

- 缓存章节索引、筛选结果、分组选择统计和队列计数，降低重复排序与扫描。
- 确认成功入队只发布一次选择清空，并保持稳定反馈动画。

### 里程碑 4：验证与交付

- 增加格式识别、HTML 200 拒绝、损坏文件重下、完整性清单、缺失页恢复、host 并发及渐进恢复测试。
- 运行完整测试和 27 张布局快照，构建安装 1.7.0，核对版本后提交。

## 验证方式

- JPEG、PNG、GIF、WebP、AVIF 能识别；HTML、JSON、空文件和截断文件不能标记完成。
- 已有有效页不发请求；损坏页会被替换；中断后只补缺失页。
- 同一 Copy host 的章节和图片请求不会突破预算；触发冷却后停止，恢复先并发 1。
- 34 话与大量章节数据下验证点击、Shift、Command、拖拽、折叠和队列筛选。
- `swift test --scratch-path /tmp/mangaglass-1.7.0-tests`。
- 独立执行快照矩阵并运行 `bash scripts/build_app.sh --install`。

## 风险

- 旧版本固定使用 `.jpg` 扩展名，实际内容可能是 PNG/WebP；校验应按内容接受旧文件，避免无意义重下。
- 清单写入过于频繁会抵消性能优化，需要批量或节流保存。
- 同一 host 调度器必须在取消时释放许可，避免队列永久阻塞。

## 决策记录

- 决策：有效旧文件按魔数接受，即使扩展名与内容不同；新文件使用真实格式扩展名。
  原因：兼容历史下载，同时修正未来文件类型。
- 决策：清单记录已验证页面，但只在阶段检查点和结束时原子写入。
  原因：兼顾异常恢复和磁盘写入频率。
- 决策：冷却结束后的三个成功章节使用并发 1，随后恢复 Copy 正常并发 2。
  原因：避免刚解除风控便重新形成请求波峰。
- 决策：解析后的图片地址写入各章节隐藏清单，不写入全局队列快照。
  原因：既能在重启后继续复用图链，也避免队列每次状态保存时重复编码大量 URL，保持队列管理流畅。

## 意外发现

- 若把每页图片 URL 直接存入队列快照，长队列会显著放大快照，并使每次状态持久化变慢。实现改为章节清单持久化，队列内只保留运行期缓存。

## 结果与回顾

- 加入队列成功后继续清空当前漫画选择；按钮在准备、成功和已在队列中三种状态间原位反馈，并保留减少动态效果兼容。
- 首页缓存筛选／排序后的章节分组，分组标题单次计算选中数；队列不再因下载消息或每行隐式动画触发整表刷新。
- 下载响应增加 MIME 与图片魔数双重校验；有效旧文件复用，损坏文件删除并重下，新文件按真实格式扩展名保存。
- 每章原子写入 `.mangaglass-manifest.json`，记录图链、预期页数、已验证页面和完成状态；重试及重启恢复时复用图链并只补缺失或损坏页面。
- Copy 章节解析与图片请求共享请求预算；异常会增加间隔，冷却后先以并发 1 完成三个章节，再恢复正常章节并发 2。
