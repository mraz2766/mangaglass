# ExecPlan：修复卷与章节选择网格

## 摘要

修正下载页卷／章节区域不易辨认和点击的问题。恢复章节按钮的轻底色、边界与明确选中反馈，压缩分类筛选和漫画摘要占用的空间，保持现有选择与下载逻辑。

视觉主张：使用原生、紧凑而清晰的选择网格，让点击目标成为章节区的主要视觉结构。

内容计划：顶部只负责搜索与分类可见性，分组标题负责整组选择，网格负责逐话选择，底栏负责确认入队。

交互主张：悬停明确可点击范围，选中状态同时改变勾选框、背景和边框，分类展开使用短促的系统动画。

## 用户价值

- 每个章节的完整点击范围清晰可见。
- 单话、整组和分类显示的含义不再混淆。
- 分类较少时不再浪费章节列表空间。

## 范围

范围内：下载页章节网格、分组标题、分类筛选、窄窗口漫画摘要和底部选择栏。

范围外：解析、下载、持久化、队列和其他页面行为。

## 约束

- 保持 macOS 13 和现有 SwiftUI 架构。
- 保留点击、Shift 连选、Command 追加和拖拽选择。
- 本次属于普通 UI 修正，版本从 `1.4.0` 升至 `1.4.1`。
- 完成后构建并替换 `/Applications/MangaGlass.app`，提交中文 `feat:` commit。

## 已确认事实

- 未选章节当前没有底色或边框，点击范围在视觉上不可见。
- 分类列表即使只有两个项目也固定占用最高 `96 pt` 的滚动区域。
- 窄布局漫画摘要当前可高达 `76 pt`。

## 实施计划

### 里程碑 1：恢复章节网格

- 章节按钮改为 `38 pt` 高、最小宽 `160 pt`、间距 `8 pt`、圆角 `6 pt`，添加轻底色与细边框。
- 加强选中、悬停、按下和禁用状态，并保留完整标题提示。

### 里程碑 2：明确整组与分类操作

- 分组标题同行显示已选数和总数，整组按钮使用次级按钮样式并显示部分选中状态。
- 分类使用“显示”语义，少量分类按内容高度显示，超过默认数量后提供展开入口。

### 里程碑 3：压缩与验证

- 窄窗口摘要控制在 `56 pt`，收紧下载页主要区块间距。
- 构建、安装并在实际应用中验证点击、选择、滚动和窗口适配。

## 验证方式

- `swift build --scratch-path /tmp/mangaglass-chapter-grid-build`
- `bash scripts/build_app.sh --install`
- 检查安装应用的两个 Bundle 版本均为 `1.4.1`。
- 使用已有 34 话漫画检查章节按钮、整组选择、分类区高度和固定底栏。

## 风险

- 章节区保留拖拽手势，需确认最小拖动距离不会抢占普通点击。
- 自适应网格必须使用章节容器宽度，避免固定列数再次引入裁切。

## 决策记录

- 决策：恢复清晰的分组按钮网格。
  原因：用户明确选择该布局，且最符合大量章节的同屏浏览需求。
